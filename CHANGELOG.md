# CHANGELOG

0.8.217 - re-linked the two prebuilt runtimes that ship inside the Arduino tarball, both of which were scanner findings no base bump could reach. **Go stdlib:** `arduino-builder` was linked against `go1.14.4` (grype: 297 stdlib CVEs, 18 of them critical); it is now rebuilt from upstream commit `99ac98e` with Go 1.25.13 in a builder stage. That commit -- not `master` -- is the one IDE 1.8.19 was cut from and the last that pins `arduino-cli v0.0.0-20210514123546`; later commits pull a 2022 `arduino-cli` whose sketch loader requires the `.ino` to be named after its directory, which `cmd.sh` does not do, so they fail every build with `main file missing from sketch`. The build also needs `go.zipexe` bumped to v1.0.2: v1.0.0 nil-derefs in `debug/elf` when it scans a binary from a modern Go linker, so `go.rice` panics in `init()`. **JRE:** the bundled Oracle JRE 1.8.0_191 (`BUILD_TYPE="commercial"`) is replaced by Temurin 8u462, the redistributable build at the same CPU level as Oracle's licence-gated 8u461. Debian 13 ships no openjdk-8 at all, so the JRE has to come from the Temurin tarball; the IDE itself is still Java (`cmd.sh` runs `arduino --verify` and `--install-library`), so it cannot be dropped. Verified by building all three Dockerfiles and running the build-chain tests (`esp8266`, `esp32`, `negative-cflags`) against them.

0.8.216 - fixed the `deployFat` branch filter, which had never matched. `only: master, test` is a single YAML scalar, and CircleCI matches a scalar as one literal branch name, so it matched no branch at all: **`deployFat` never ran and the `latest` tag was never published by CI.** Only `test` ran on `master`. The single-value filters on `deploy32`/`deploy8266` were unaffected, which is why `esp32` and `esp8266` published normally. Now a proper YAML list.

0.8.215 - added `tests/negative-cflags.sh`, a guard-the-guard test: it rebuilds with `cflags` stripped out of `environment.json` and requires the build to **fail**, for that specific reason. The positive build-chain tests assert that `cflags` arrive by having the dummy sketch `#error` without them; if those guards ever stopped tripping, the positive tests would keep passing while checking nothing. CI restructured so that **every branch builds exactly one image and every deploy job verifies the image it is about to push**: `deployFat`/`deploy32`/`deploy8266` now run `build` → build-chain test → `push` and no longer `requires: test`, and `test` is the gate only for branches that do not deploy. Previously `master` built the ~6 GB Fat image twice per pipeline, and the `esp32`/`esp8266` branches built a Fat image they never ship.

0.8.213 - fixed `cflags` breaking every ESP32 build. `--pref` *replaces* a preference rather than appending to it, and `compiler.cpp.extra_flags` is not a free user slot on every core: esp8266 leaves it empty, but the esp32 core defaults it to `-MMD -c` and expands it first in `recipe.cpp.o.pattern`. Overwriting it therefore dropped `-c`, so the compiler tried to *link* each translation unit and the build died with ``undefined reference to `main'``. `cmd.sh` now reads the core's own `compiler.cpp.extra_flags` out of its `platform.txt` and keeps it in front of the user's flags, so this stays correct if the core changes its defaults. Found by the build-chain tests added in 0.8.212 — the ESP32 target had never been exercised with `cflags` before.

0.8.212 - fixed six defects that made both targets unable to produce firmware, all of them older than the Debian 13 / DHI base-image work and all reproducible in the previously published image. **esp8266:** every build failed with `unrecognized command-line option '-cppflags'` — the core expands `{compiler.warning_flags}` into a GCC `@`-response-file path, but no `compiler.warning_level` was set, so the placeholder resolved to an empty string; `cmd.sh` now passes `--pref compiler.warning_level=none`. **esp32:** every build failed with `Error: esp32: Unknown package` because the Fat image cloned `arduino-esp32` into a directory layout Arduino 1.8.x does not recognise — it now installs to `/opt/arduino/hardware/espressif/esp32`, matching `Dockerfile.esp32`, so both images share the FQBN `espressif:esp32:<board>`. **esp32:** `python3-serial` added — a manual core install ships `esptool` as a Python package that does `import serial`, so `elf2image` died with `ModuleNotFoundError`. **esp32:** the build then reported SUCCESS while exporting the 3 kB partition table as `firmware.bin`; the application image is now selected explicitly, excluding the `.bootloader`/`.partitions`/`.merged` artefacts. **All targets:** `cflags` and every `environment.json` define were silently dropped on any rebuild in a workspace that still had a `build/` directory — Arduino's preprocessed copy of `environment.json` (with a `#line` directive prepended) shadowed the real one and broke `jq`; input discovery now prunes the build directory. **All targets:** empty `--pref` values no longer clobber board defaults (`build.flash_ld` was emitted twice, both times possibly empty).

Added a build-chain test harness (`tests/`): CI now runs the real entrypoint against a dummy project inside each freshly built image and asserts a plausible application image comes out, instead of only checking that `docker build` succeeds. The dummy sketch fails to compile when its `cflags` do not arrive, and each target is built twice so a stale `build/` directory cannot silently regress. `Dockerfile.esp32` and `Dockerfile.esp8266` are now verified before they are pushed.

0.8.209 - upgraded base image to `debian:13.5-slim` (Debian 13 "trixie"; dropped the now-removed `software-properties-common` package). Fixed the `cflags` feature (added in 0.8.0) which never actually reached the builder: the value is now appended to `CFLAGS` and passed as a single `--pref compiler.cpp.extra_flags` token, so multi-flag values work end-to-end.

0.8.0 - added support for `cflags` variable in `environment.json` – variable is directly transformed into `--pref compiler.cpp.extra_flags` arduino builder argument.

0.7.9 - Support for `environment.json` using to update `environment.h` file to allow custom builds from same source.
